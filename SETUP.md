# Подключение сервера NEAR (Supabase)

Без этого шага приложение работает в **демо-режиме**: аккаунты и публикации хранятся только на одном телефоне.
После подключения Supabase все пользователи видят публикации друг друга, фото хранятся на сервере, а вход работает с любого устройства.

Время: около 15 минут. Бесплатно.

---

## Шаг 1. Создайте проект

1. Откройте https://supabase.com и нажмите **Start your project**. Войдите через GitHub (аккаунт momQQ).
2. Нажмите **New project**.
3. Заполните:
   - **Name:** `near`
   - **Database Password:** придумайте и сохраните (понадобится редко)
   - **Region:** ближайший, например `Central EU (Frankfurt)`
4. Нажмите **Create new project** и подождите 1–2 минуты.

## Шаг 2. Создайте таблицы

1. Слева откройте **SQL Editor** → **New query**.
2. Откройте файл `supabase/schema.sql` из архива, скопируйте **весь** текст и вставьте в окно.
3. Нажмите **Run**. Внизу должно появиться `Success. No rows returned`.

Скрипт создает таблицы, правила доступа, хранилище для фото и автоматические уведомления. Его можно запускать повторно.

## Шаг 3. Настройте вход по email

1. Слева **Authentication** → **URL Configuration**.
2. **Site URL:** `https://momqq.github.io/near/app.html`
3. В **Redirect URLs** нажмите **Add URL** и добавьте: `https://momqq.github.io/near/**`
4. Нажмите **Save**.

Это нужно, чтобы ссылки из писем (подтверждение почты, сброс пароля) открывали ваше приложение.

**Подтверждение почты.** Убедитесь, что включено: Authentication → Sign In / Providers → Email → **Confirm email** = ON. Тогда после регистрации человек получает письмо и входит только после нажатия на ссылку.

> Бесплатный почтовый сервер Supabase отправляет всего несколько писем в час — для теста хватит. Для настоящего запуска подключите свой SMTP (Authentication → Emails → SMTP Settings), например бесплатный тариф Resend или Brevo.
> Текст письма можно перевести на русский: Authentication → Emails → Templates → Confirm signup.

## Шаг 4. Скопируйте ключи

1. Слева внизу **Project Settings** (шестеренка) → **API** (или кнопка **Connect** вверху).
2. Скопируйте:
   - **Project URL** — вида `https://abcdefgh.supabase.co`
   - ключ **anon public** (начинается с `eyJ...`) или **Publishable key** (`sb_publishable_...`)

⚠️ Ключ **service_role / secret** никуда не вставляйте и никому не показывайте.

## Шаг 5. Вставьте ключи в приложение

1. На GitHub откройте репозиторий → папка `js` → файл `config.js`.
2. Нажмите карандаш ✏️ (Edit).
3. Вставьте ключи между кавычками:

```js
SUPABASE_URL: "https://abcdefgh.supabase.co",
SUPABASE_ANON_KEY: "eyJhbGciOi...",
```

4. Нажмите **Commit changes**.
5. Через 1–2 минуты откройте `https://momqq.github.io/near/app.html`. Желтая плашка "Демо-режим" должна исчезнуть.

## Шаг 6. Проверьте

1. Зарегистрируйтесь (если подтверждение почты включено — откройте письмо и нажмите ссылку).
2. Создайте публикацию с фото.
3. В Supabase: **Table Editor → posts** — появилась строка; **Storage → post-media** — появилось фото.
4. Откройте приложение на другом телефоне под другим аккаунтом — публикация видна в ленте и на карте.

---

## Шаг 7. ИИ-проверка фото и сообщений (по желанию)

Фото в публикациях и чатах, а также текст сообщений будут проверяться бесплатным сервисом модерации OpenAI. Подозрительное фото размывается с предупреждением, а жалоба автоматически попадает модератору.

1. Зарегистрируйтесь на https://platform.openai.com → **API keys** → **Create new secret key**. Скопируйте ключ (`sk-...`). Модерация бесплатная, но OpenAI может попросить привязать карту.
2. В Supabase: **Edge Functions** → **Secrets** → **Add new secret**: имя `OPENAI_API_KEY`, значение — ваш ключ → Save.
3. **Edge Functions** → **Deploy a new function** → **Via Editor**. Название: `moderate`. Удалите пример кода, вставьте весь текст из файла `supabase/functions/moderate/index.ts` → **Deploy function**.
4. **SQL Editor** → выполните:
   ```sql
   update public.app_settings set ai_moderation = true;
   ```
5. На GitHub в `js/config.js` поставьте `AI_MODERATION: true` → Commit.

Выключить: `update public.app_settings set ai_moderation = false;` и `AI_MODERATION: false`.

## Шаг 8. Назначить себя модератором

После регистрации в приложении: **SQL Editor** → выполните (подставьте свой email):

```sql
update public.profiles set is_admin = true
where id = (select id from auth.users where email = 'ваш@email.kz');
```

В профиле появится кнопка **🛡 Модерация**: жалобы, скрытие и восстановление публикаций, удаление, бан пользователей.

Снять бан вручную: `update public.profiles set banned = false where id = '...';`

## Шаг 9. Обновление сервера (v6–v9)

Если сервер уже настроен, после загрузки новых файлов на GitHub:
**SQL Editor** → New query → вставьте весь `supabase/schema.sql` → **Run**. Скрипт безопасно запускать повторно: данные не удаляются.

Что изменится:
- бакет `chat-media` станет приватным: фото, видео и голосовые из переписки открываются только участникам по временной ссылке (1 час);
- при отмене SOS всем, кто откликнулся (комментарий или лайк), придет уведомление; SOS остается в истории со статусом "отменен".

- v7: пол, район, значок "подтвержден" ✓, статус "был(а) в сети", вход через Google.
- v9: подписки на push-уведомления и их отправка, удаление аккаунта.
- v10: изменений в базе нет (лента грузится порциями по существующим индексам).
- v8: ответы на комментарии, описание профиля, скрытие статуса "в сети", превью и размеры фото/видео, лимит видео 50 МБ.

**Видео с iPhone.** Если видео снято в формате HEVC (по умолчанию на новых iPhone), на Android и в Chrome оно может не воспроизвестись. Приложение проверяет видео перед загрузкой и подскажет. Надежный вариант: на iPhone — Настройки → Камера → Форматы → "Наиболее совместимый". Перекодирования на сервере пока нет: на бесплатном Supabase его не сделать.

**Поддержка.** Чтобы в Настройках работала кнопка "Поддержка", впишите почту в `js/config.js`: `SUPPORT_EMAIL: "ваша@почта"`.

Если вы обновили функцию `moderate` (шаг 7), разверните ее заново: в ней появилась поддержка приватных фото чатов.

## Шаг 10. Подтверждение почты (письма через Brevo, бесплатно)

Встроенная почта Supabase отправляет письма только участникам вашей команды, поэтому нужен свой почтовый сервис. Brevo бесплатно отправляет до 300 писем в день.

1. Зарегистрируйтесь на https://www.brevo.com (Sign up free).
2. **Senders, Domains & Dedicated IPs** → **Senders** → **Add a sender**: имя `NEAR`, ваша почта (например, ваш Gmail). Подтвердите ее по письму от Brevo.
3. **SMTP & API** → вкладка **SMTP** → **Generate a new SMTP key**. Скопируйте ключ и логин (вида `xxxx@smtp-brevo.com`).
4. В Supabase: **Authentication** → **Emails** → **SMTP Settings** → включите **Enable custom SMTP**:
   - Sender email: почта из пункта 2, Sender name: `NEAR`;
   - Host: `smtp-relay.brevo.com`, Port: `587`;
   - Username: логин из пункта 3, Password: SMTP-ключ → **Save changes**.
5. **Authentication** → **Sign In / Providers** → **Email** → включите **Confirm email** → Save.
6. По желанию — письмо на русском: **Authentication** → **Emails** → **Templates** → **Confirm signup**:
   - Subject: `Подтвердите почту в NEAR`
   - Body:
     ```html
     <h2>Добро пожаловать в NEAR!</h2>
     <p>Нажмите кнопку, чтобы подтвердить почту и войти:</p>
     <p><a href="{{ .ConfirmationURL }}">Подтвердить почту</a></p>
     <p>Если вы не регистрировались, просто удалите это письмо.</p>
     ```

После этого новые пользователи получают письмо, а после подтверждения у них появляется значок ✓. Если письмо в "Спаме" — это нормально для отправки с Gmail; со своим доменом письма доходят лучше.

## Шаг 11. Вход через Google

Понадобится ваш аккаунт Google, около 10 минут.

1. Откройте https://console.cloud.google.com → сверху **Select a project** → **New project** → имя `NEAR` → Create.
2. Меню → **APIs & Services** → **OAuth consent screen** (или **Google Auth Platform**) → **Get started**:
   - App name: `NEAR`, User support email: ваша почта;
   - Audience: **External**; Contact email: ваша почта → Create.
3. **Audience** → **Publish app** (иначе войти смогут только тестовые пользователи).
4. **Clients** (или **Credentials** → **Create credentials** → **OAuth client ID**):
   - Application type: **Web application**, имя `NEAR web`;
   - Authorized JavaScript origins: `https://momqq.github.io`
   - Authorized redirect URIs: `https://aswcegzkbzuqwfpxwuqw.supabase.co/auth/v1/callback`
   - Create → скопируйте **Client ID** и **Client secret**.
5. В Supabase: **Authentication** → **Sign In / Providers** → **Google** → включите, вставьте Client ID и Client secret → Save.
6. **Authentication** → **URL Configuration**:
   - Site URL: `https://momqq.github.io/near/app.html`
   - Redirect URLs → Add URL: `https://momqq.github.io/near/**`

Готово: кнопка "Продолжить с Google" на экране входа заработает. После первого входа приложение попросит указать пол и район. Аккаунты Google сразу получают значок ✓.

## Шаг 12. Защита от ботов (Cloudflare Turnstile, бесплатно)

1. Зарегистрируйтесь на https://dash.cloudflare.com → слева **Turnstile** → **Add widget**:
   - Widget name: `NEAR`; Hostname: `momqq.github.io`; Widget mode: **Managed** → Create.
2. Скопируйте **Site Key** и вставьте в `js/config.js`: `TURNSTILE_SITE_KEY: "ваш_site_key"`. Загрузите `config.js` на GitHub и подождите 1–2 минуты.
3. Только после этого: Supabase → **Authentication** → **Attack Protection** (или **Bot and Abuse Protection**) → **Enable CAPTCHA protection** → провайдер **Turnstile** → вставьте **Secret Key** → Save.

Порядок важен: если включить капчу в Supabase раньше, чем обновится сайт, вход временно перестанет работать. Обычные люди проверку почти не замечают: галочка появляется только при подозрении на бота.

## Шаг 13. Удаление аккаунта

1. Supabase → **Edge Functions** → **Deploy a new function** → **Via Editor**.
2. Имя: `delete-account`. Вставьте весь код из `supabase/functions/delete-account/index.ts` → **Deploy**.
3. Ничего больше не нужно: ключи сервера функция берет сама. Проверка входа (Verify JWT) остается **включенной**.

Теперь в Настройках → Аккаунт → "Удалить аккаунт" работает: стираются фото, видео, файлы переписок, публикации, комментарии, сообщения и сам аккаунт.

## Шаг 14. Push-уведомления

1. Supabase → **Database** → **Extensions** → найдите `pg_net` → включите (если `schema.sql` уже включил — пропустите).
2. **Edge Functions** → **Deploy a new function** → **Via Editor** → имя `push` → вставьте код из `supabase/functions/push/index.ts` → **Deploy**.
3. Откройте функцию `push` → **Details** (или Settings) → выключите **Verify JWT / Enforce JWT verification** → Save. Вызов защищен секретом из базы.
4. **Edge Functions** → **Secrets** (или Project Settings → Edge Functions) → добавьте три секрета:
   - `VAPID_PUBLIC_KEY` — значение из `js/config.js` (строка `VAPID_PUBLIC_KEY`);
   - `VAPID_PRIVATE_KEY` — секретный ключ, который я прислал в чате. **Не загружайте его на GitHub!**
   - `VAPID_SUBJECT` — `mailto:ваша@почта`.
5. Запустите `schema.sql` еще раз (шаг 9), если не делали после обновления.

Проверка: откройте NEAR на телефоне → Профиль → ⚙ → "Push-уведомления на телефон" → включите. Попросите друга написать вам сообщение и сверните приложение.

**iPhone:** push работают только если NEAR добавлен на экран "Домой" (Safari → Поделиться → На экран "Домой") и открыт с иконки, iOS 16.4 или новее. **Android:** работает в Chrome сразу.

Что приходит: личные сообщения, комментарии и ответы, лайки, заявки в друзья, происшествия и SOS в выбранном радиусе (1–10 км). Ночью (23:00–08:00) только SOS, если включены тихие часы. Повторы по одной переписке или публикации заменяют друг друга, а не копятся. Пока приложение открыто на экране, push не показывается: там уже звучит сигнал.

## Шаг 15. Обновление до v11 (безопасность, PostGIS, запросы в чатах)

Делайте сначала на **тестовом проекте** (staging), потом на рабочем. Перед запуском на рабочем: **Database → Backups** — убедитесь, что есть свежая резервная копия.

1. **Database → Extensions** → включите `postgis` (схема `extensions`) и `pg_net`. По желанию — `pg_cron` для ежедневной уборки.
2. **SQL Editor** → вставьте весь `supabase/schema.sql` → **Run**. Скрипт идемпотентный: повторный запуск ничего не ломает. Тот же блок v11 лежит отдельно в `supabase/migrations/011_v11.sql`.
3. **Edge Functions** → обновите три функции кодом из `supabase/functions/`:
   - `push` — Verify JWT **выключен**;
   - `moderate` — Verify JWT **выключен** (проверка внутри: секрет базы или токен автора). Теперь она же переносит файлы скрытых публикаций в приватный бакет `post-quarantine` и стирает файлы удаленных;
   - `delete-account` — Verify JWT **включен**.
4. ИИ-проверка: секрет `OPENAI_API_KEY` в Edge Functions, затем в SQL: `update app_settings set ai_moderation = true;`. Проверку теперь запускает база, а не телефон. Если ИИ недоступен, фото остается "на проверке" и попадает в очередь модератора.
5. Ежедневная уборка (если включен `pg_cron`):
   ```sql
   select cron.schedule('near-cleanup', '17 3 * * *', 'select public.near_cleanup()');
   ```
   Стирает старые служебные записи и черновики старше суток вместе с файлами.
6. **Authentication → URL Configuration → Redirect URLs**: оставьте только свои адреса (`https://momqq.github.io/near/app.html` и адрес staging). **Authentication → Emails**: срок ссылки — 1 час.
7. **Authentication → Attack Protection**: включите Turnstile (шаг 12) — тогда капчу проверяет сервер, а не только телефон.
8. Модераторы: `update profiles set is_moderator = true where id = '...';` (модератор скрывает и возвращает публикации, разбирает жалобы и апелляции). Банить и назначать модераторов может только администратор (`is_admin`).

## Шаг 16. Обновление до v12 (проверка почты, SOS, медиа, фильтры, избранные места)

Порядок тот же: сначала **staging**, потом рабочий проект.

1. **Резервная копия.** Database → Backups: убедитесь, что есть копия не старше суток. Раз в месяц делайте **проверку восстановления**: создайте пустой проект, восстановите в него копию (или `pg_dump` → `psql`) и откройте приложение с ключами этого проекта в режиме `ENV: "staging"`. Запишите дату проверки и время восстановления.
2. **SQL Editor** → весь `supabase/schema.sql` → **Run** (или только `supabase/migrations/012_v12.sql`, если база уже на v11). Скрипт идемпотентный. Что меняется:
   - SOS: срок 3 часа ставит сервер, второй SOS не создается даже при двух одновременных нажатиях;
   - публиковать, комментировать и писать сообщения можно только с подтвержденной почтой (вход через Google считается подтвержденным) и с заполненным профилем (пол и согласие с правилами);
   - переписка удаленного аккаунта остается у собеседника 30 дней (только чтение), потом стирается вместе с файлами;
   - новые таблицы `saved_places` (избранные места, до 5, видит только владелец) и `feedback` (сообщения об ошибках);
   - сортировка ленты "Новое / Рядом / Для вас", фильтры "сегодня / неделя / друзья" на сервере.
3. **Edge Functions** → обновите `moderate` и `push` кодом из `supabase/functions/` (настройки Verify JWT те же, что в шаге 15):
   - `moderate` теперь проверяет каждый загруженный файл: настоящий тип по первым байтам (JPEG, PNG, WebP, HEIC, MP4, MOV, в том числе HEVC), размер до 20 МБ, удаляет GPS и прочие метаданные из видео. Неподходящий файл удаляется, автор получает уведомление;
   - `push` присылает "Происшествие рядом с местом" только тем, кто включил уведомления для своего избранного места.
4. **Защита от ботов**: Authentication → Attack Protection → **Enable Captcha protection** → Turnstile, вставьте **Secret Key**. В `js/config.js` — `TURNSTILE_SITE_KEY`. Без этого капча проверяется только на телефоне.
5. **Письма**: Authentication → Emails → SMTP (Brevo, шаг 10). Кнопка "Отправить письмо еще раз" в приложении работает не чаще раза в минуту.
6. **Поддержка**: если есть почта поддержки — впишите ее в `SUPPORT_EMAIL` в `js/config.js`, в настройках появится строка "Поддержка по email". Без почты работает форма "🐞 Сообщить об ошибке": обращения видит администратор в **Модерация → Состояние**.
7. **Staging**: отдельный проект Supabase с теми же шагами 2–6, в `js/config.js` — `ENV: "staging"` и его ключи. Сайт staging — отдельная ветка или репозиторий GitHub Pages. Адрес staging добавьте в Redirect URLs.
8. **Секреты**: ключ VAPID (private), `OPENAI_API_KEY`, ключ Turnstile (secret) и `service_role` хранятся **только** в Edge Functions → Secrets / настройках Supabase. В репозиторий GitHub они не попадают; в `js/config.js` — только публичные ключи.

### Откат v12

1. Верните на GitHub Pages файлы v11 (`app.html`, `js/`, `css/`, `sw.js`, `media/`).
2. В SQL уберите триггеры v12 (команды — в начале `supabase/migrations/012_v12.sql`) и запустите `011_v11.sql` повторно.
3. Таблицы `saved_places` и `feedback` можно не удалять: v11 их не использует.

### Режимы config.js

`ENV: "prod"` — рабочий сервер, `"staging"` — тестовый проект со своими ключами, `"demo"` — без сервера, данные только на телефоне. В `staging` и `prod` приложение **никогда** не переходит в демо: при сбое показывает ошибку.

### Лимиты частоты (начальные, уточняются по логам)

Хранятся в `app_settings.limits` (на аккаунт / на сеть за период): публикации 10 в час, SOS 2 в час, комментарии 60 в час, сообщения 120 в час, жалобы 20 в сутки, заявки в друзья 50 в сутки. Лимит по сети в 4–5 раз выше — с запасом на общий Wi-Fi и мобильный NAT. Звонок 112 лимиты не затрагивают.

```sql
update app_settings set limits = limits || '{"post":[20,80,"1 hour"]}'::jsonb;  -- пример изменения
```

### Проверка прав на своем компьютере (необязательно)

`sh supabase/tests/run_tests.sh` — чистая база, схема два раза, 120 автоматических проверок прав и правил (гость, A, B, C, модератор, администратор). Нужен Postgres 15+. `sh supabase/tests/functions/run.sh` — проверка функций push, delete-account и проверки медиа без Supabase (Node 22+ и ffmpeg для тестовых видео).

### Сборка приложения

Код интерфейса — модули в `src/app/`. После правок: `node tools/build.mjs` — собирает `js/app.js` и `app.html`, проверяет синтаксис и ESLint, затем сжимает файлы (esbuild) в `*.min.js` / `*.min.css` — их и подключает страница. Если esbuild не установлен (`npm i -D esbuild`), файлы копируются без сжатия. На GitHub загружаются и исходники, и собранные файлы.

### Наблюдаемость

- Ошибки приложения — таблица `client_errors` (без токенов, email и текстов сообщений), у каждой есть `correlation_id` = заголовок `x-request-id` запроса.
- Логи функций: **Edge Functions → Logs**, строки в формате JSON с `corr`.
- Показатели пилота: в приложении у администратора — **Модерация → Состояние**, или SQL `select public.kpi_summary(30);`.
- Оповещения: **Reports / Log Explorer** → создайте алерты на рост ошибок 5xx, на `push_log.failed` и на объем Storage.

## Шаг 17. Обновление до v14.9 (NEAR Shield, встречи, общие чаты, видеоплеер)

Порядок тот же: сначала **staging**, потом рабочий проект. Личных сообщений больше нет — вместо них общий чат города и чаты районов.

1. **Резервная копия.** Database → Backups: копия не старше суток. Дополнительно снимите свою копию: `pg_dump "строка подключения" -Fc -f near_before_v14_9.dump`. Без копии миграцию не запускайте.
2. **SQL Editor** → `supabase/migrations/014_v14_9.sql` → **Run** (база должна быть на v12). Если база новая — весь `supabase/schema.sql`. Скрипт идемпотентный, повторный запуск безопасен. Что добавляется:
   - вход по никнейму или почте, никнейм уникальный (без учета регистра и похожих букв), общий текст ошибки входа;
   - одна активная сессия: вход с нового устройства подтверждается кодом из письма (10 минут, 5 попыток, повтор через 60 с);
   - блокировки с номером решения (NS-#####), сроком на сервере и апелляциями (решение за 72 часа, рассматривает другой модератор);
   - Risk Score и связанные аккаунты (обход блокировки, массовая регистрация);
   - NEAR Clean: маскировка мата RU/KZ/EN, мошенничество и опасные ссылки, 10 сообщений в минуту, 3 публикации за 10 минут, повтор за 60 с блокируется;
   - встречи (9 категорий), отметка присутствия, отзывы, репутация (видна после 3 отзывов и 3 встреч);
   - общие чаты (город и 8 районов) с ответами и реакциями;
   - медиа через приватное хранилище `post-staging`: uploading → processing → pending_review → approved / rejected / failed. В ленту попадает только проверенный файл;
   - журнал аудита (нельзя изменить), хранение: журнал входов 30 дней, события риска 180 дней.
3. **Edge Functions** → создайте две новые функции кодом из `supabase/functions/`:
   - `shield-login` — **Verify JWT: выключено** (вход, лимиты попыток, Turnstile);
   - `shield-mail` — **Verify JWT: выключено** (письма с кодами);
   - обновите `moderate` и `delete-account` (настройки те же).
4. **Секреты** (Edge Functions → Secrets, только там):
   - `BREVO_API_KEY` **или** `RESEND_API_KEY` — для писем с кодом;
   - `MAIL_FROM` — адрес отправителя, например `NEAR <no-reply@ваш-домен>`;
   - `TURNSTILE_SECRET_KEY` — секретный ключ Turnstile;
   - `OPENAI_API_KEY` — проверка изображений и текста в кадре.
   `service_role`, VAPID private и эти ключи в GitHub не попадают. В `js/config.js` — только публичные.
5. **Видео-обработчик (FFmpeg worker)**. Без него видео остается в статусе "обрабатывается" и никому не показывается — это безопасно.
   - папка `tools/media-worker/`: `docker build -t near-media-worker .`
   - запуск (Render, Fly.io, любой VPS): `docker run -d --read-only --tmpfs /tmp --cpus 1 --memory 1500m --pids-limit 64 -e SUPABASE_URL=... -e SUPABASE_SERVICE_ROLE_KEY=... -e OPENAI_API_KEY=... near-media-worker`
   - что делает: обрезка до 30 с, MP4 H.264/AAC до 720p, faststart, удаление GPS, обложка, проверка. Готовое видео уходит модератору (pending_review).
   - временно выключить видео: `update app_settings set shield = shield || '{"video":false}' where id = 1;`
6. **Очистка по расписанию**: Database → Cron → новое задание раз в час: `select public.shield_cleanup();`
7. **Включение по шагам** (через SQL Editor):
   - сначала без жестких проверок: `update app_settings set shield = shield || '{"enforce_sessions":false,"admin_mfa":false}' where id = 1;`
   - через 1–2 дня, когда все обновили приложение: `... '{"enforce_sessions":true}'`
   - затем MFA для персонала (п. 8): `... '{"admin_mfa":true}'`
8. **Роли и MFA.** Роли: `profiles.is_admin`, `is_moderator`, `is_auditor`. Authentication → Multi-Factor → включите TOTP. Каждый сотрудник: Профиль → ⚙ → NEAR Shield → "Подключить" (раздел MFA). Пока `admin_mfa = true`, без второго фактора права модератора не работают.
9. **Пилот встреч**: создавать встречи могут участники пилота — `update profiles set meetings_pilot = true where nickname in ('...');`. Открыть всем: `... '{"meetings_pilot_only":false}'`.
10. **Проверка восстановления**: раз в месяц восстановите копию в пустой проект (`pg_restore -d "строка" near_before_v14_9.dump`) и откройте приложение в режиме `ENV: "staging"`.

### Откат v14.9

- **Мягкий** (данные сохраняются): SQL Editor → `supabase/migrations/014_v14_9_rollback.sql`. Выключает сессии и MFA, снимает новые триггеры, возвращает функции v12. Затем верните на сайт файлы v12. Повторно включить v14.9 — снова запустить `014_v14_9.sql` и п. 7.
- **Полный**: восстановление копии из п. 1 (`pg_restore --clean`).

## Если что-то не работает

| Что видно | Что сделать |
|---|---|
| "Не удалось загрузить библиотеку Supabase" | Проверьте интернет и правильность `SUPABASE_URL` |
| "Invalid API key" / ничего не грузится | Скопируйте ключ заново, без пробелов и переносов |
| Письмо не приходит | Проверьте "Спам"; лимит бесплатных писем — несколько в час; для теста отключите Confirm email |
| Ссылка из письма открывает не то | Проверьте Шаг 3 (Site URL и Redirect URLs) |
| "Нет прав на это действие" | Запустите `schema.sql` еще раз целиком |
| Фото не загружается | Storage → проверьте бакеты: `post-media` (Public), `chat-media` и `post-quarantine` (не Public) |
| Не приходят новые сообщения без обновления | Database → Replication (Publications) → `supabase_realtime`: включены `messages`, `posts`, `notifications`, `conversations` |
| "Слишком часто" | Сработал лимит частоты (шаг 15). Подождите или увеличьте лимит |
| Лента пустая после v11 | Не включен PostGIS: Database → Extensions → `postgis`, затем снова `schema.sql` |
| Фото "проверяется" и не открывается | Функция `moderate` не развернута или нет секрета `OPENAI_API_KEY`. Проверьте шаг 7 или выключите ИИ-проверку |

Безопасность: ключ anon можно хранить в открытом коде — защиту обеспечивают правила доступа из `schema.sql` (каждый может менять только свои публикации, видеть только свои уведомления и сохраненное).
